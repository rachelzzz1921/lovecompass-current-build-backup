# 套二 · ROS 关系测评体系 V2.0

> **产品名**：ROS 关系测评系统 · 套二  
> **版本**：V2.0  
> **机器可读规范**：[`../data/ros_suite_spec_v2.json`](../data/ros_suite_spec_v2.json)  
> **题库数据**：[`../data/suite2_ros_female.json`](../data/suite2_ros_female.json)、[`../data/suite2_ros_male.json`](../data/suite2_ros_male.json)  
> **数据库 slug**：`s02_ros_female` / `s02_ros_male` · 评分模型 `ROS_V3`

---

## 1. 产品定位

| 项 | 说明 |
|---|---|
| **测什么** | 「你们之间怎么样」——评估对象是一段**具体的关系**，作答者心里必须有一个真实存在的人 |
| **与套一关系** | 套一 = 自我底片（SELF）；套二 = 关系测评（ROS）。双层叠加 → 「你 × 这段关系」的真实互动模式 |
| **收费** | 需兑换码解锁（非免费） |
| **增值** | 联动套一后，AI 可做深度双层分析 |
| **裂变** | 购买后可免费邀请一位伴侣参与；双方完成 → 双人报告双向免费解锁 |

### 1.1 五层理论模型

| 代码 | 名称 | 含义 |
|---|---|---|
| **AT** | 吸引层 | 关系起点与吸引力 |
| **IN** | 互动层 | 日常相处与沟通质量 |
| **CO** | 兼容层 | 价值观与生活方式匹配度 |
| **EV** | 演化层 | 关系发展轨迹 |
| **RK** | 风险层 | 关系红线与潜在问题 |

## 2. 核心流程

### 2.1 发起方（购码用户）

1. 进入测试 → 询问是否有伴侣匹配码  
2. **无码**：购码开始测试  
3. **有码**：免费开始，预加载对方数据  
4. 完成 60 题 → 获得**单人关系报告**  
5. 系统生成**关系码** + 专属邀请链接  
6. 分享给伴侣  

### 2.2 受邀方（伴侣）

1. 点开链接 → 自动预填发起方关系码  
2. **独立注册**账号（不是子账号）  
3. 完成对应性别版本 60 题 → 获得**个人单人报告**  
4. 双方数据自动合并  
5. **双人报告**双向免费解锁

## 3. 关系码（Relation Code）

| 项 | 说明 |
|---|---|
| **格式** | `ROS-XXXX-XXXX` |
| **存储内容** | 五维得分 (AT/IN/CO/EV/RK)、套一依恋类型（如有）、用户性别、生成时间戳 |
| **作用** | 数据凭证；无需账号绑定，输入即可关联双方数据 |

## 4. 关系阶段（9 段曲线）

| # | 阶段 | 特征 | 曲线位置 |
|---|---|---|---|
| 1 | 怦然相遇 | 新鲜感最强，滤镜最厚，所有缺点都是可爱 | 上升 |
| 2 | 渐入佳境 | 开始展示真实的自己，关系在加深 | 峰值 |
| 3 | 暗流初现 | 第一次感受到摩擦，开始有不确定感 | 下降 |
| 4 | 磨合阵痛 | 误解和争执开始出现，考验真正开始 | 低谷 |
| 5 | 倦怠低谷 | 消耗感明显，开始怀疑这段关系 | 最低点 |
| 6 | 十字路口 | 有过放弃的念头，但还没走 | 转折点 |
| 7 | 重建信任 | 经历过风浪，开始真正理解彼此 | 上升 |
| 8 | 深度联结 | 不只是喜欢，是真正懂得 | 上升 |
| 9 | 并肩同行 | 稳定、成熟、有未来感 | 峰值 |

**时长校准（前置题）**

- 暗恋 / 暧昧：锁定阶段 ①②，不出现高阶阶段  
- 三年以上：降低 ①② 权重，侧重 EV / IN 得分  
- 已婚 / 长期：低共鸣解读为「需要新鲜感」，**非**「关系消退」

## 5. 关系类型（6 种）

| 原命名 | 新命名 | 特征 |
|---|---|---|
| 滋养型 | **彼此生长** | 让你成为更好的自己，被看见、被支持、有成长 |
| 共生型 | **难舍难分** | 深度融合，分不清是爱还是需要 |
| 平行型 | **温水同行** | 不冷不热，舒适但缺少真正联结 |
| 消耗型 | **心甘情愿地累** | 付出多于回报，但还在坚持 |
| 燃烧型 | **烈火烹油** | 极好极坏，情绪过山车 |
| 过渡型 | **此刻刚好** | 舒适但没有未来感 |

判定规则与 tagline 见题库 JSON 中的 `relationship_type_rules`。

## 6. 五维结构与题量

| 维度 | 名称 | 权重 | 方向 | 题量 | 女版聚焦 | 男版聚焦 |
|---|---|---:|---|---:|---|---|
| AT | 吸引基础 | 0.20 | 正向 | 10 | 他当初吸引你的是什么，现在还是吗 | 你对她的吸引感有没有在减退 |
| IN | 互动质量 | 0.30 | 正向 | 16 | 他有没有真正听你说话，冲突后有没有修复 | 相处是否轻松，她的情绪对你的影响 |
| CO | 兼容程度 | 0.25 | 正向 | 12 | 生活规划能不能走到一起 | 家庭观、消费观、生活节奏差距 |
| EV | 关系走向 | 0.15 | 正向 | 12 | 你在关系里是在成长还是萎缩 | 这段关系有没有让你有动力往前走 |
| RK | 风险信号 | 0.10 | **反向** | 10 | 共用核心，部分题目差异化 | 同上 |

**合计**：60 题 + 2 道前置校准题（不计分）。

**题型（8 种）**：`slider` · `scenario` · `binary` · `choice` · `scale` · `mood` · `card` · `rank`

**语言风格**

- 女版：情感感受类——「你感觉到」「你有没有觉得」  
- 男版：行为事实类——「你们通常会」「你发现」  

**特殊适配**：暗恋 / 未在一起状态有专属题目替换版。

## 7. 双人匹配分析

### 7.1 共鸣指数

- **展示下限**：55 分（人情世故原则：分数向上平移，底部托底）  
- **计算公式**：  
  `AT×0.20 + IN×0.30 + CO×0.25 + EV×0.15 + (100-RK)×0.10`  
  若某层双方差值 > 20，指数 **-3**

| 原始分 | 展示分 | 段位 | 描述 |
|---|---|---|---|
| 81–100 | 88–96 | 心有灵犀 | 很难被替代的默契 |
| 61–80 | 75–87 | 深度共鸣 | 真实联结，值得珍惜 |
| 41–60 | 65–74 | 温柔磨合 | 在彼此靠近的路上 |
| 0–40 | 55–64 | 初见雏形 | 还在成形，有空间也有可能 |

### 7.2 感知差值（模板）

> 你们对这段关系的感受有一些不同的地方——你感受到的联结感比他/她高出一些。这不代表谁对谁错，更可能的是你们表达爱的方式不太一样。有时候，付出的人感受更深，接收的人习以为常——试着让他/她知道，你在意哪些细节。

### 7.3 维度错位解读

| 维度 | 含义 |
|---|---|
| AT | 吸引感不对等，一方比另一方更投入 |
| IN | 对相处质量的感受完全不同 |
| CO | 对这段关系的未来判断不一样 |
| EV | 一个在成长，一个在原地 |
| RK | 双方都察觉到了问题，但可能没说出来 |

### 7.4 依恋碰撞（15 组）

套一依恋类型 × 套二双人数据 → 命名组合解读。完整映射见 JSON `coupleMatchAnalysis.attachmentCollision` 及题库 `attachment_collision_map`。

示例：安全型×焦虑型 → **避风港与浪**；焦虑型×回避型 → **欢喜冤家**（经典追逃）。

## 8. 报告设计

### 8.1 单人报告

1. 关系类型判定  
2. 关系曲线定位（9 阶段之一）  
3. 五维雷达图  
4. 三条 AI 洞察（优势 / 注意点 / 建议）  
5. 关系码 + 邀请链接  

### 8.2 双人报告

1. 共鸣指数 + 段位名  
2. 关系天气预报（晴天 / 多云转晴 / 阴雨 / 暴风雨前）  
3. 双人关系曲线定位  
4. 双层叠加雷达图（SELF + ROS）  
5. 感知差值分析  
6. 依恋碰撞分析  
7. AI 三条专属建议  
8. 关系处方签  
9. 社交分享卡片  

### 8.3 处方签暖场语

| 阶段区间 | 暖场语要点 |
|---|---|
| 阶段 7–9 | 走过风浪，处方帮你们继续走好 |
| 阶段 1–3 | 彼此发现期，帮这段时间更扎实 |
| 阶段 4–6 | 认真对待关系，帮把问题说清楚（不是「你们有问题」） |
| 低共鸣 + 长期 | 钝化很正常，帮重新找到彼此频道 |

### 8.4 处方签格式（示例）

```
┌─────────────────────────┐
│  Rx  你们的关系处方      │
│                         │
│  主诉：联结感不均衡      │
│  建议：每周一次          │
│        不带手机的        │
│        两小时对话        │
│  复诊：三个月后          │
└─────────────────────────┘
```

## 9. 五条核心原则

1. **人情世故原则**：语言委婉，分数调优，**绝不劝分**  
2. **独立用户原则**：受邀方为独立用户，**优先获得个人报告**  
3. **真实精准原则**：性别视角差异化，贴合真实关系感受  
4. **传播友好原则**：结果适配社交分享，自带传播属性  
5. **校准纠错原则**：关系时长 + 阶段校准结果，避免常识性错误

| 用途 | 位置 |

**开发约定**

- 题目、选项、权重、关系类型判定、阶段规则 → **入库 JSONB**，不写死在 Python/前端  
- 评分服务读取 `scoring_models` 中 `ROS_V3` 配置执行计算  
- AI 报告 / 聊天读取：ROS 五维 + 套一 SELF 六维 + 依恋类型 → 双层分析  
- 关系码、双人合并、邀请链路 → 待 V2 业务 API 实现（规范已定义，表结构见 `relation_pairs` 等迁移）

**与套一联动**

```
SET · 01 SELF（套一）  →  依恋类型、六维底片
SET · 02 ROS（套二）   →  五维关系画像、关系码、双人共鸣
AI 分析师 / 报告       →  SELF + ROS 叠加解读
```
