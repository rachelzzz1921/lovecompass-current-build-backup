## 一、当前技术取向

我已按你的最新说明调整后续实施优先级。当前阶段不强行切换到 Next.js/Prisma 全家桶，而是在 Lovable 已生成并可构建的前端基础上继续推进，优先把 **Supabase 数据库、独立后端 API、题型契约、跳转闭环和 AI Adapter** 做稳。等到需要管理后台、SEO 页面或统一前后端工程时，再评估是否迁移到 Next.js App Router 与 Prisma。

| 项目 | 当前采用 | 近期是否需要注册/补充 | 说明 |
|---|---|---:|---|
| 前端框架 | TanStack Start / Vite / React | 不需要 | 已能构建，继续沿用 Lovable 原工程，避免现在重写造成返工。 |
| 后端 API | FastAPI | 不需要 | 已有骨架，适合快速对接 Supabase 与 AI Adapter。 |
| 数据库 | Supabase PostgreSQL | 已注册，待补数据库密码/连接串 | 需要执行迁移与导入题库。 |
| ORM | 暂不引入 Prisma | 暂不需要 | 当前 Python 后端用 `psycopg` 直接连库，等 schema 稳定后再决定是否引入 ORM。 |
| AI | 智谱 API + Adapter | 需要 API Key 时再向你要 | 先写适配层，不把业务代码绑定到智谱 SDK。 |
| 认证 | 先预留 Supabase Auth | 稍后配置 | 当前开发使用 demo user，生产前必须接 Auth。 |
| 缓存/限流 | 暂不引入 Upstash Redis | 暂不需要 | MVP 阶段可先用数据库与应用限流，流量上来再加。 |

| 部署 | Vercel 临时链接优先 | 部署前需要 Vercel 项目权限/环境变量 | 前端可走 Vercel preview；后端可先用独立服务地址，或后续统一迁移。 |

## 二、Supabase 下一步需要的信息

你已经提供了项目的 publishable key，这类 key 可以用于浏览器端初始化 Supabase 客户端；但真正执行数据库迁移、后端写入与服务端权限控制时，还需要服务端私密配置。为了安全起见，私密 key 不应写入前端 `.env`，也不应提交到公开仓库。

| 信息 | 是否已具备 | 用途 | 是否敏感 |
|---|---:|---|---:|
| Supabase URL | 已在前端 `.env` 中存在 | 前端和后端连接项目 | 否 |
| Publishable/Anon Key | 已有 | 浏览器端读写受 RLS 保护的数据 | 低敏，但仍不建议随意公开传播 |
| Database URL / Password | 待提供或由你在控制台复制 | 后端运行迁移、导入题库、服务端查询 | 高敏 |
| Service Role Key | 待生产阶段决定是否使用 | 管理端/后端绕过 RLS 的服务操作 | 极高敏 |
| Auth Redirect URL | 部署前配置 | 登录后跳回 Vercel 临时链接 | 否 |

## 三、AI Adapter 策略

AI 接入不会直接把业务逻辑写死为某一家模型。后端将暴露一个统一接口，业务层只调用 `generate(prompt)`；底层根据 `AI_PROVIDER` 选择智谱或后续其他模型。这样以后从智谱切换到 Anthropic、OpenAI-compatible 或自托管模型时，只改适配层和环境变量，不改测试、评分、聊天和报告业务代码。

> 目标抽象：业务层只知道“生成文本”，不知道供应商、模型名、鉴权方式和请求格式。

## 四、上线策略

当前建议使用 **本地联调 → Vercel 临时链接 → 再决定生产部署** 的路径。Vercel preview 适合给你快速验收前端交互和真实 `attemptId` 链路；后端如果继续使用 FastAPI，则需要一个可访问的后端地址。短期可以先在开发环境或临时服务跑通，之后再决定是否迁移到 Vercel Serverless、Railway/Render/Fly.io，或改为 Next.js API Routes 统一部署。

| 阶段 | 前端 | 后端 | 数据库 |
|---|---|---|---|
| 本地联调 | `npm run dev` | `uvicorn app.main:app --reload --port 8000` | Supabase 远程库 |
| 临时验收 | Vercel Preview | 临时 API 地址 | Supabase 远程库 |
| 生产前 | 自定义域名或 Vercel Production | 稳定后端部署 | RLS/Auth/备份策略完善 |
