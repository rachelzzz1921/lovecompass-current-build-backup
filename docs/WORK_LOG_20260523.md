## 三、本轮关键技术结论

Supabase 数据库连接串可用，真库迁移已经成功落地。题库导入过程中暴露的约束问题不是连接问题，而是数据库约束与题库真实业务字段不一致；通过新增兼容迁移后已解决。

完整答题闭环暴露了两个更接近生产环境的问题。第一，后端原型使用固定 demo 用户写入兑换事件和答题记录，因此真库中必须存在对应的 `auth.users` 记录；该问题已通过幂等 demo 用户种子迁移解决。第二，Supabase pooler 与 psycopg 自动 prepared statements 在长连接池场景下可能冲突，因此当前数据库连接封装已显式禁用自动 prepared statements。

前后端 slug 方面，数据库中的真实测试套件 slug 是 `s01_self_female` 与 `s01_self_male`，来自题库 JSON 中 `suite.id` 的规范化。前端下一步应以兑换码接口返回的 `suiteSlug` 为准，而不是继续依赖静态产品 ID。
